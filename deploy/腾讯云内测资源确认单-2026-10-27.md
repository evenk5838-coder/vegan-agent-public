## 仅采用现有Compose交付方案

```text
手机浏览器 ── HTTPS ── Caddy ── Next.js网页
                            └── FastAPI API ── PostgreSQL
                                      └── 私有原图/录音卷
```

使用仓库现有 `deploy/compose.yaml`，保留Next.js、FastAPI、PostgreSQL与后台任务消费方式，不切换云数据库/CloudBase网关或增加另一套部署架构。一个API实例、一个Uvicorn worker，不开启reload或横向扩容。

- 产品入口仅由Caddy对外发布80/443。API8000、前端3000、数据库5432不开放公网，数据库仅在私有容器网络。
- SSH管理入口只允许管理员明确的来源IP，使用SSH密钥；本轮没有配置防火墙或更改账户权限。
- 数据库、私有媒体、Caddy证书和备份使用独立持久卷；网页与Caddy不挂载私有媒体卷，私有图片不能静态公开。
- 前后端同源，生产Origin为确认后的HTTPS域名，Cookie启用Secure。高德域名设置、手机定位/录音及推送仍需真实HTTPS和真机核验。
- 运行密钥在服务器本地私下填入项目外 `/etc/shushi/runtime.env`，权限600；不发聊天、不进入Git、镜像、前端构建参数或日志。沿用已批准的API限额，另行核对真实调用费用范围。

## 批准后才执行的备份、恢复与回滚入口

以下命令均为准备材料，本次没有执行Docker命令。完整前置条件见同目录 `README.md` 和 `VALIDATION.md`。部署前先在批准的机器完成镜像构建、权限与健康检查，并记录源码版本、镜像digest及迁移版本。

```bash
# 配置文件由用户在服务器本地准备，不把内容输出到聊天或日志。
python3 deploy/preflight.py --env-file /etc/shushi/runtime.env

# 获得停写/备份授权后执行；备份名必须尚不存在。
docker compose --env-file /etc/shushi/runtime.env -f deploy/compose.yaml --profile ops build ops-backup
docker compose --env-file /etc/shushi/runtime.env -f deploy/compose.yaml stop api
docker compose --env-file /etc/shushi/runtime.env -f deploy/compose.yaml --profile ops run --rm ops-backup backup before-change-UNIQUE
docker compose --env-file /etc/shushi/runtime.env -f deploy/compose.yaml --profile ops run --rm ops-backup drill before-change-UNIQUE
docker compose --env-file /etc/shushi/runtime.env -f deploy/compose.yaml start api

# 独立空目标恢复：需另一份私有RESTORE_POSTGRES_PASSWORD及明确恢复授权。
python3 deploy/preflight.py --env-file /etc/shushi/runtime.env --restore-profile
docker compose --env-file /etc/shushi/runtime.env -f deploy/compose.yaml --profile restore build ops-restore
docker compose --env-file /etc/shushi/runtime.env -f deploy/compose.yaml --profile restore run --rm ops-restore inspect before-change-UNIQUE
docker compose --env-file /etc/shushi/runtime.env -f deploy/compose.yaml --profile restore run --rm ops-restore restore before-change-UNIQUE --confirm-target FINGERPRINT_FROM_INSPECTION

# 程序回滚：先确认旧镜像digest及数据库兼容性，准备私有previous-release.env，
# 除RELEASE_TAG外沿用同一已核对配置。旧镜像须已存在，不重建覆盖旧标签。
docker compose --env-file /etc/shushi/previous-release.env -f deploy/compose.yaml stop api web
docker compose --env-file /etc/shushi/previous-release.env -f deploy/compose.yaml up -d --no-build --no-deps api web
```

恢复入口拒绝源目标相同、非空库/媒体目录或错误目标指纹；备份需校验清单与SHA-256。独立恢复不会自动切换业务流量，切换数据库/媒体卷需另审配置并获授权。数据库与文件系统不能做同一事务，恢复期间API保持停止。禁止用 `down -v` 删除业务卷，也不直接向业务库执行 `pg_restore --clean` 或未经审查的Alembic降级。
